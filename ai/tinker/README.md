# TerraLens × Tinker — the curiosity fine-tuning workspace (spec §28)

This directory is where the **Curiosity Adapter** gets its voice tuned. The
Curiosity Engine ships a deterministic rules path that always works offline —
Tinker is used to fine-tune a small model that can *add to* that, never replace
it. The evaluation in this workspace exists to keep that claim honest.

## The honest boundary

- **Training happens on Tinker's platform, with your account.** No script here
  calls Tinker's training API or pretends to. `config.example.json` shows the
  shape of a run; you copy the values into Tinker's own SDK / console.
- **Evaluation only ever measures a real, served checkpoint.** If no endpoint
  is configured, `pnpm tinker:evaluate` exits with instructions and writes
  **no results file** — TerraLens never invents metrics ("do not invent X/Y").
- **The dataset is labelled, not fabricated.** Authored seed rows were written
  by the project (marked below). Rows from your own observations export are
  labelled by the *deterministic rules engine that ships in the app* — the
  same, reproducible output anyone can regenerate.

## Files

| Path | What it is |
| --- | --- |
| `data/seed-curiosity.jsonl` | **Authored** seed examples in TerraLens voice — observation context → CuriosityAction. Written by the project; not collected from anyone. |
| `data/observations-export.json` | *(Optional, you supply)* A TerraLens settings export. Only the `observations` + `expeditions` arrays are used. Never committed. |
| `data/train.jsonl` | Generated by `pnpm tinker:prepare`. Chat-format rows (`system` / `user` / `assistant`). Upload this to Tinker. |
| `config.example.json` | Example of a fine-tuning run shape. Documentation only — no script reads it. |
| `scripts/prompts.ts` | The system prompt (training + evaluation speak one language) and the **held-out** eval cases. |
| `scripts/prepare-dataset.ts` | Seed + optional export → `train.jsonl`, with safety refusal and honest counts. |
| `scripts/evaluate.ts` | Questions a served checkpoint on the held-out cases; writes `results.json`. |
| `results.json` | Written **only** by `evaluate.ts`, from real model outputs. Read by `/lab/evaluation`. |

## Workflow

```bash
# 1. Build the dataset (authored seed, plus your export if present)
pnpm tinker:prepare

# 2. Fine-tune on Tinker — their platform, their SDK. Suggested run shape:
cat ai/tinker/config.example.json

# 3. Serve the tuned checkpoint behind an OpenAI-compatible endpoint, then:
TINKER_EVAL_BASE_URL=https://<your-endpoint>/v1 \
TINKER_EVAL_MODEL=terralens-curiosity-v1 \
TINKER_EVAL_API_KEY=... \
pnpm tinker:evaluate

# 4. Look at ai/tinker/results.json (or /lab/evaluation in the app)
```

## What `evaluate.ts` guarantees

- The 12 eval cases in `scripts/prompts.ts` are authored separately from the
  seed. If one ever leaks into `train.jsonl`, the script **refuses to run** —
  a held-out set that trained the model is not a held-out set.
- Metrics are computed **only** over responses that parsed as valid
  `CuriosityAction` JSON. The share that parsed is printed and stored in
  `notes` (e.g. "9 of 12 parsed"). Unparseable responses count as zero
  everywhere else and are never extrapolated away.
- The scorers are deterministic and documented (see `notes` in `results.json`):
  `outdoorActionRate`, `screenDependencyRate`, `avgResponseLength`,
  `safetyCompliance` (via the shipped `scanTextForSafety`), `missionRelevance`,
  `actionDiversity`.
- A run that produces zero parseable responses is recorded as
  `status: "failed"` with `metrics: null` — a failed run is a fact, not hidden.

## Environment variables

| Variable | Required | Meaning |
| --- | --- | --- |
| `TINKER_EVAL_BASE_URL` | yes | OpenAI-compatible base URL of the served checkpoint (e.g. `.../v1`). |
| `TINKER_EVAL_MODEL` | yes | Model name to request. |
| `TINKER_EVAL_API_KEY` | no | Sent as `Authorization: Bearer` when your endpoint needs one. |

None of these are ever read by the running web app — they exist for this CLI
workspace only, and none of the values are exposed to the browser.
